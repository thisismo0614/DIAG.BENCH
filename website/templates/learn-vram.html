VRAM 용량이 프로그램마다 다르게 보이는 이유

같은 그래픽카드를 두고 어떤 도구는 8GB, 어떤 도구는 16GB, 또 어떤 도구는 512MB라고 합니다. 대부분 도구가 틀린 것이 아니라, 서로 다른 값을 보고 있는 것입니다. 무엇이 무엇인지 구분하면 혼란이 사라집니다.

VRAM이라 불리는 세 가지 값

값무엇인가어디서 보이나
전용 비디오 메모리
Dedicated Video Memory		 그래픽카드에 물리적으로 붙어 있는 메모리. "RTX 4060 8GB"의 그 8GB입니다. 작업 관리자 "전용 GPU 메모리", nvidia-smi
공유 시스템 메모리
Shared System Memory		 전용 메모리가 모자랄 때 빌려 쓸 수 있는 시스템 RAM. 보통 시스템 RAM의 절반이 상한입니다. 작업 관리자 "공유 GPU 메모리"
현재 할당량
Current / Adapter RAM		 지금 이 순간 잡혀 있는 양. 계속 변합니다. 일부 WMI 조회, 모니터링 도구

"8GB인데 16GB로 보인다" → 전용 + 공유를 더한 값입니다.
"8GB인데 512MB로 보인다" → 지금 실제로 쓰이고 있는 양입니다.

Windows가 4GB를 넘겨 보고하지 못하는 문제

가장 자주 혼란을 일으키는 원인입니다. 오래된 WMI 속성인 Win32_VideoController.AdapterRAM은 32비트 값이라 4,294,967,295바이트(약 4GB)까지밖에 표현하지 못합니다.

Get-CimInstance Win32_VideoController |
  Select-Object Name, AdapterRAM

Name           : NVIDIA GeForce RTX 4060 Ti 16GB
AdapterRAM     : 4293918720        ← 실제 16GB인데 약 4GB로 보고

16GB 카드도, 8GB 카드도 전부 "약 4GB"로 나옵니다. 이 값을 그대로 표시하는 도구는 큰 용량의 그래픽카드에서 반드시 틀립니다. Microsoft도 이 속성을 더 이상 신뢰할 수 없다고 안내하고 있습니다.

그래서 DIAG.BENCH는 NVIDIA 카드에서 nvidia-smi를 우선해서 씁니다. 드라이버가 직접 보고하는 값이라 이 제약이 없습니다. 다만 AMD·Intel 그래픽에는 대응하는 도구가 없어 현재 지원 범위가 아닙니다 — 그 경우 값을 추측하지 않고 "확인 불가"로 표시합니다.

내장 그래픽은 아예 다릅니다

내장 그래픽(Intel UHD/Iris, AMD Radeon Graphics)에는 전용 메모리가 거의 없거나 아주 적습니다. 시스템 RAM을 나눠 쓰기 때문입니다.

  • BIOS에서 미리 떼어주는 양이 있고(보통 64MB~2GB), 나머지는 필요할 때 동적으로 가져갑니다.
  • 그래서 값이 계속 변하고, 도구마다 다른 시점의 값을 보여줍니다.
  • 메모리 대역폭이 곧 그래픽 성능이라 듀얼 채널 여부와 메모리 속도가 체감 성능에 크게 영향을 줍니다.

내장 그래픽 시스템에서 게임 성능이 기대에 못 미친다면, 그래픽 설정보다 메모리가 싱글 채널인지부터 확인하는 편이 빠릅니다.

그래서 무엇을 봐야 하나

  1. "이 카드가 몇 GB짜리인가"를 알고 싶다 → 전용 비디오 메모리를 보세요. 제품명에 적힌 값과 같아야 합니다.
  2. "지금 게임이 VRAM이 모자란가"를 알고 싶다 → 전용 메모리 사용량이 상한에 붙어 있고 공유 메모리 사용이 늘고 있다면 부족한 상태입니다. 시스템 RAM으로 넘어가면 눈에 띄게 느려집니다.
  3. 공유 메모리 용량 자체는 신경 쓰지 않아도 됩니다. "쓸 수 있는 상한"일 뿐 실제로 그만큼 쓰이지 않습니다.

직접 확인하는 방법

# NVIDIA — 가장 정확
nvidia-smi --query-gpu=name,memory.total,memory.used --format=csv

# 전체 — DirectX 진단 도구
dxdiag

작업 관리자 → 성능 → GPU에서도 전용/공유가 나뉘어 표시됩니다. 두 값이 따로 보인다는 점만 알고 있으면 대부분의 혼란은 사라집니다.
