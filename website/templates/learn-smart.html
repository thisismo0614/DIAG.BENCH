SMART 값 읽는 법

SMART를 열어보면 수십 개 항목이 쏟아집니다. 대부분은 판단에 쓸 수 없는 값이고, 실제로 "이 디스크를 교체해야 하나"에 답하는 항목은 몇 개뿐입니다. 무엇을 보고 무엇을 무시해야 하는지 정리합니다.

SMART가 무엇인가

저장장치가 스스로 자기 상태를 기록해 두는 기능입니다. 읽기 오류가 몇 번 났는지, 못 쓰게 된 영역을 몇 개 대체했는지, 전원이 몇 시간 켜져 있었는지 같은 것을 누적합니다. 디스크가 직접 세는 값이라는 점이 중요합니다 — 밖에서 추측한 수치가 아닙니다.

항목어떻게 읽나

읽을 때 자주 걸리는 함정

정규화 값과 원시 값은 다릅니다

SMART 항목에는 보통 두 숫자가 붙습니다. 정규화 값(100에서 시작해 나빠질수록 내려감)과 원시 값(실제 횟수). 정규화 값이 100이라고 안심하면 안 됩니다 — 제조사마다 계산이 달라서, 원시 값에 이미 문제가 잡혀 있는데 정규화 값은 여유롭게 표시되기도 합니다. 원시 값을 보세요.

임계값이 비어 있는 경우가 있습니다

일부 장치는 임계값 자리에 숫자 대신 ---를 보고합니다. "임계값을 정의하지 않았다"는 뜻이지 값이 없다는 뜻이 아닙니다. 이걸 처리하지 못하는 도구는 해당 항목을 통째로 건너뛰어, 정작 봐야 할 재할당 섹터가 화면에서 사라지는 일이 생깁니다. DIAG.BENCH도 이 경우를 처리하도록 파서를 고친 적이 있습니다.

종료 코드를 성공/실패로 읽으면 안 됩니다

SMART 조회에 널리 쓰이는 smartctl은 종료 코드가 비트마스크입니다. 0이 아니라고 해서 실패한 것이 아니라, 각 비트가 서로 다른 사실을 나타냅니다.

bit 0  명령 자체가 실패
bit 1  장치가 열리지 않음
bit 2  일부 SMART 명령 실패
bit 3  디스크가 "실패 예상" 상태
bit 4  과거에 임계값을 넘은 적 있음
...

즉 값이 정상적으로 나왔는데도 종료 코드는 0이 아닐 수 있습니다. 이걸 단순히 "0이 아니면 오류"로 처리하면 멀쩡한 조회 결과를 버리게 됩니다.

SMART가 정상이어도 고장날 수 있습니다

가장 중요한 한계입니다. SMART는 이미 일어난 일을 기록합니다. 앞으로 일어날 일을 예측하는 기능이 아닙니다.

  • 컨트롤러 고장이나 갑작스러운 전기적 손상은 SMART에 아무 흔적을 남기지 않고 일어납니다.
  • 실제 고장의 상당수는 SMART가 모두 정상인 상태에서 발생합니다.
  • 반대로 재할당 섹터가 몇 개 있어도 몇 년을 더 쓰는 경우도 있습니다.

SMART가 깨끗하다는 것은 "지금까지 기록된 문제가 없다"는 뜻이지 "앞으로 안전하다"는 뜻이 아닙니다. 백업을 대신할 수 있는 진단은 없습니다.

그래서 언제 교체해야 하나

  1. 대기 중 섹터가 0이 아니다 → 지금 백업하세요. 판단은 그다음입니다.
  2. 재할당 섹터가 계속 늘어난다 → 교체를 준비합니다. 한 번 세고 마는 것이 아니라 몇 주 간격으로 다시 재서 증가 여부를 보는 것이 핵심입니다.
  3. NVMe의 Critical Warning이 0이 아니다 → 장치가 스스로 경고한 상태입니다.
  4. 값은 정상인데 이상 증상이 있다 → SMART만으로 판단하지 말고 이벤트 로그의 디스크 오류를 함께 확인하세요.
